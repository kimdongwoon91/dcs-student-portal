# Core Beliefs

> 상태: ✅ v1.0

---

## Belief 1: 학생은 번호가 아니라 사람이다

**Because** 학번·석차로만 표현되는 학교 시스템이 학생을 숫자로 환원한다. 우리 앱은 그 반대여야 한다.

**So we**
- ✅ 화면에서 항상 닉네임으로 호칭 ("지수님 안녕하세요")
- ✅ 실명은 서버에서 인증 후 즉시 폐기, UI에 절대 노출하지 않는다

**We don't**
- 🚫 "학번 20XXXXX 학생" 같은 비인격적 표현
- 🚫 실명 + 학번 병기

---

## Belief 2: 성장은 비교가 아니라 자기 자신과의 여정이다

**Because** "전교 N등" "반에서 몇 등" 같은 표현은 불안을 팔아 참여를 만드는 방식이다. 우리는 그렇게 하지 않는다.

**So we**
- ✅ "지난 평가보다 환산총점이 올랐어요" 같은 자기 비교 표현 사용
- ✅ 성취수준(A/B/C 등)을 있는 그대로 표시

**We don't**
- 🚫 석차, 백분율 순위, 반 평균 대비 표현
- 🚫 "평균 이하" "하위 XX%" 같은 표현

---

## Belief 3: 보안은 기능이 아니라 전제다

**Because** 학생 성적·생기부는 민감 개인정보다. 한 번의 유출이 신뢰를 영구히 무너뜨린다.

**So we**
- ✅ 모든 데이터 조회는 서버에서, 쿠키 학번 기준으로만
- ✅ 이름 평문 저장 금지, 노션·Supabase 키 서버 전용

**We don't**
- 🚫 클라이언트에 API 키 노출
- 🚫 타 학생 데이터 조회 가능한 엔드포인트 설계

---

## Belief 4: 교사 흐름을 방해하지 않는다

**Because** 교사는 이미 노션에서 학생 데이터를 관리한다. 새로운 입력 도구를 강요하면 도입 자체가 실패한다.

**So we**
- ✅ 노션 읽기 전용; 교사 워크플로우 변경 없음
- ✅ 학생이 상담 신청하면 노션에 행 생성 (교사는 노션에서 확인)

**We don't**
- 🚫 교사용 별도 관리 화면 개발
- 🚫 노션 데이터 구조 임의 변경

---

## Intentional Non-Decisions

- 알림 Push 방식 (브라우저 인앱 알림으로 충분, 외부 푸시 미결정)
- 다크모드 (1차 미지원, 이후 결정)
